### Prompt Structure
Think step-by-step about how to generate a C++ program that computes the Mandelbrot set within the specified region and outputs it in PBM P4 format. Follow these instructions:

1. **Understand the Mandelbrot Set Calculation**:
   For each complex number \( c \) in the grid over the range `[-1.5, 0.5]` (real part) and `[-1.0, 1.0]` (imaginary part), compute the sequence:
   \[
   z_{n+1} = z_n^2 + c,
   \]
   where \( z_0 = 0 \). Count iterations until either:
   - The magnitude of \( z_n \) exceeds **4.0** (escape threshold), or
   - The iteration count reaches **50**.

   If the sequence escapes, the point is *not* in the Mandelbrot set; otherwise, it *is*.

2. **Grid Mapping**:
   For a given resolution `N`, map each grid pixel to a corresponding complex number \( c \) by linear interpolation:
   - Real part: \( x = -1.5 + (0.5 - (-1.5)) \cdot \frac{i}{N} \)
   - Imaginary part: \( y = -1.0 + (1.0 - (-1.0)) \cdot \frac{j}{N} \).

3. **PBM P4 Format**:
   The output must follow PBM P4:
   - Header line: `P4` (case-sensitive).
   - First line: `N N` (the resolution squared, i.e., \( N^2 \)).
   - Binary data: A packed bitstream where each pixel’s iteration count is written as 8 bits (zero-padded to an integer value). Bits are packed MSB-first per row.

4. **C++ Code Requirements**:
   - Use `std::cout` for output.
   - Accept `N` as a command-line argument.
   - Precompute constants like \(-1.5\), \(0.5\), etc., to avoid redundant calculations.
   - Handle edge cases (e.g., invalid `N`, rounding errors in interpolation).

---
**Chain-of-Thought Steps**:
- Write the Mandelbrot iteration function.
- Implement the grid mapping for each pixel \((i,j)\).
- Construct the binary PBM output by iterating over all pixels and packing their iteration counts.
- Validate that the code adheres to the exact specification for escape threshold (4.0), max iterations (50), and PBM format.

### Key Requirements
- **Language**: Pure C++17 or later; no external libraries allowed.
- **Input Handling**:
  - Command-line argument: `N` (must be an integer ≥ 2).
  - Validate `N` to avoid invalid ranges (e.g., reject non-integer inputs).
- **Iteration Logic**:
  - Use exactly 50 iterations per point.
  - Escape threshold is the magnitude of \( z_n \) exceeding 4.0 (compute as \(|z_n| > 4.0\)).
- **Output Format**:
  - No extra whitespace or lines; strictly PBM P4.
  - Binary pixels packed MSB-first, zero-padded per row (e.g., for iteration count `k`, bits must represent the *binary* form of \( k \) as an integer).
  - Example: Iteration counts 3 and 7 (binary `011` and `111`) are written as `[0b011][0b111]` = packed bytes `0x35`.
- **Edge Cases**:
  - Handle rounding errors during interpolation gracefully.
  - Ensure correctness for the boundary points of the plot region (e.g., \( c \) values where \(|z_n|\) just exceeds 4.0 at max iterations).

### Variable Values
- **Max Iterations**: `50`
- **Escape Threshold**: `4.0` (explicitly check \(|z_n| > 4.0\))
- **Plot Region**:
  - Real axis: \( x \in [-1.5, 0.5] \)
  - Imaginary axis: \( y \in [-1.0, 1.0] \)

### Notes
- The PBM P4 packing requires the binary values of iteration counts (not their decimal representation). For example:
  - Iteration count `k = 3` (binary `0b00...011`) is written as two bytes: `0x00`, `0x03`.
  - The model must ensure correct bit-packing per row, zero-padded to an integer value (e.g., a row with iteration counts `[256, 1]` becomes bytes `0xFF` + `0b00000001` = `0xFF`, `0x01`).
- Ambiguity risk: Ensure the model distinguishes between "escape" (reaching threshold) and "max iterations hit." Both must render as 50 (black pixel) if interpreted as part of the set.
- Known pitfall: Floating-point precision in interpolation may affect edge cases near the plot boundaries. The prompt emphasizes rounding to nearest integer for grid mapping.
