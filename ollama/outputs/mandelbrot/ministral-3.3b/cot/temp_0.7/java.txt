### **Prompt Structure**
Think step-by-step about implementing the Mandelbrot set in Java for the CLBG problem. The goal is to generate a program that:
1. Takes an integer `N` (e.g., `200`) as a command-line argument.
2. Computes the Mandelbrot set over the region `[-1.5, 0.5]` × `[-1.0, 1.0]` with **50 iterations** and threshold `lim = 4` (since `2² = 4`).
3. Maps pixel coordinates `(x,y)` to complex numbers `C` using:
   `real(C) = 2.0 * x / N - 1.5`, `imag(C) = 2.0 * y / N - 1.0`.
4. For each point, iterate `Z = Z² + C` starting from `(0,0)` until `|Z|² > lim` (escape).
5. If the point escapes after ≤50 iterations, it belongs to the set; otherwise, it does not.
6. Output binary data in **PBM P4 format** (packed 8 pixels/byte, MSB=set bit) with a header `"P4\nN N"`.

---
### **Key Requirements**
- **Java syntax**: Strict adherence to Java conventions (e.g., `System.out.write` for binary output).
- **Input handling**: Read `N` from `args[0]`; exit on invalid input.
- **Precision**: Use `double` arithmetic with exact bounds (`lim=4.0`).
- **Padding**: Pad last row bytes to multiples of 8 (e.g., if `N=23`, row length = 256 bits, padded to 32 bytes per row).
- **Output format**: No whitespace; binary data must match `cmp`'s validation.
- **Edge cases**:
   - N=1 → trivial output (single pixel at center).
   - Odd/even N: Handle uneven rows correctly with padding.

---
### **Variable Values**
| Parameter               | Value                  |
|-------------------------|-----------------------|
| **Max iterations**      | `50`                   |
| **Escape threshold (lim)**| `4.0` (`2.0 * 2.0`)    |
| **Region bounds (real)**| [-1.5, 0.5]           |
| **Region bounds (imag)**| [-1.0, 1.0]           |

---
### **Notes**
- **Tool use**: The LLM must compute pixel coordinates and iterate `Z` in-place for efficiency.
- **Bitmasking**: Pack pixels as bits: bit `k` of byte `i` corresponds to pixel `(8*i + k)`. MSB=set (`1`), LSB=not set (`0`).
- **Validation risk**: The LLM must ensure the output is *identical* to reference for `N=200`. Overlooking padding or iteration order could fail.
- **Precision note**: Use `double` for all calculations; floating-point errors must be minimized (e.g., avoid premature truncation).
- **Output example**: For `N=8`, the output might start like:
  ```
  P4
  8 8
  [0xAA, 0x55, ...]  # First row packed bytes (MSB=set)
  ```
