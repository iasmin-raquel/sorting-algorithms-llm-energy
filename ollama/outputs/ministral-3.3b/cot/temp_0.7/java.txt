### Prompt Structure
Act as a Java programming expert. I need you to generate precise Java code implementing the **N-body problem** for the Jovian planets (Jupiter, Saturn, Uranus, Neptune), with the Sun acting as the central mass. Follow a structured reasoning approach using Chain-of-Thought prompting:

1. First, define all constants (`PI`, `SOLAR_MASS`, `DAYS_PER_YEAR`) exactly as provided.
2. Understand the **symplectic integrator** order: velocity updates followed by position updates (Verlet integration). This requires:
   - Using the **velocity Verlet method** to update velocities and positions, accounting for mutual gravitational forces between all bodies.
   - Calculate gravitational acceleration using Newton’s law of gravitation (`G = GM/r²`).
3. Adjust initial conditions such that the total momentum of the system is zero by modifying the Sun’s velocity (**offsetMomentum**). Document this step clearly.
4. Implement:
   - A time step (`deltaTime`) of `DAYS_PER_YEAR / 1000` (adjustable via command-line argument `N`, where `N = number of steps`).
   - Energy conservation check: Print the initial and final kinetic + potential energy in floating-point `%f` format with precision `.9f`.
5. The function should be a main method that:
   - Takes `int N` (number of iterations) as a command-line argument.
   - Outputs formatted energies (`initialEnergy`, `finalEnergy`) using `System.out.printf("%.9f\n".format(...))`.

### Key Requirements
- **Strict adherence** to the provided constants and initial conditions (no approximations).
- **No hardcoding** of values unless explicitly referenced in the prompt. The target LLM must compute all derived quantities like gravitational acceleration from given masses, positions, and velocities.
- **Precision control**:
  - Gravitational forces computed with `double` precision.
  - Time stepping with `deltaTime = DAYS_PER_YEAR / N`.
- **Output format**: Exactly `%f` for energy values.
- **Symplectic integrator**: Order matters: Update all `vx/vy/vz` first, then update `x/y/z` using central differences.
- **Zero momentum**: Ensure the Sun’s velocity is recalculated to satisfy this constraint at initialization.

### Notes
1. **Ambiguity resolution**: The prompt explicitly asks the target LLM to compute all gravitational forces (e.g., `F = G*(m₁*m₂)/r²`) using only the provided masses, positions (`x,y,z`), and the constants `PI`/`SOLAR_MASS`.
2. **Zero momentum constraint**: The Sun’s velocity will be recalculated as:
   ```java
   double totalMomentumX = sum(mass_i * vel[i].x);
   double offset = -totalMomentumX; // Adjust Sun's vx by this amount.
   ```
3. **Energy calculation**: Kinetic energy (`0.5*m*v²`) summed over all bodies, plus potential energy (`-G*(m₁*m₂)/r`). Ensure no approximations in `double` arithmetic.
4. **Time step handling**: Explicitly state that `deltaTime = DAYS_PER_YEAR / N` for user-defined iterations `N`.
5. **Symplectic integrator**: The prompt enforces that `vel` updates occur before position updates, using central differences (e.g., new `x_new = x_old + deltaTime * v_current`).
