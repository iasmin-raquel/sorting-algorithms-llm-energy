### **Prompt Structure**
**Generate C++ code to simulate the n-body problem for Jovian planets under mutual gravitation.**
The program should:
1. Take `N` (number of time steps) as a command-line argument.
2. Print initial and final energy (`%.9f` format).
3. Adjust the Sun’s velocity to enforce **total momentum = 0** (via `offsetMomentum`).
4. Use a **symplectic integrator** with order: first update all velocities, then update positions.
5. Use the given constants (`PI`, `SOLAR_MASS`, `DAYS_PER_YEAR`) exactly as provided.

The code must:
- Implement acceleration via gravitational forces (directly proportional to `(mass1 * mass2) / distance^3`).
- Avoid explicit time loops for efficiency; instead, compute delta-time implicitly.
- Validate with `ndiff -abserr 1.0e-8` after `N=1000` steps.

**Example structure:**

### **Key Requirements**
- **Language**: C++ (strict syntax, no Python/fortran-style code).
- **Momentum Conservation**: Adjust Sun’s velocity to zero net momentum.
- **Symplectic Integrator**:
  - Velocity update before position update (order 4+ accuracy).
  - Do not use explicit time steps; let `N` define simulation length implicitly.
- **Precision**: Energy validation at `1.0e-8`.
- **No External Dependencies**: Only standard C++ headers (`<iostream>`, `<vector>`, `<cmath>`).
- **Input Handling**: CLI argument for `N`.

### **Notes**
1. **Symplectic Integrator**: The order must be explicit (velocities first, then positions). Assume `dt=1/DAYS_PER_YEAR` for simplicity unless otherwise noted.
2. **Energy Calculation**:
   - Initial: Sum of kinetic (`0.5 * m |v|^2`) + potential (`-G * sum_{i<j} [m_i m_j / r_ij]`).
   - Final: Repeat after `N` steps (adjust `dt` if needed).
3. **Ambiguity Risk**: The prompt avoids explicit time-stepping by letting `N` define "1 year" as a discrete unit—LLM must infer this implicitly.
4. **Performance**: Avoid nested loops; use parallelization or vectorization for gravitational force computation (e.g., `omp` or SIMD).
