### **Prompt Structure**
Act as a C++ programming expert tasked with designing an efficient implementation of the n-body problem for the Jovian planets under gravitational mutual interactions. You must adhere strictly to the given specifications while ensuring precision in calculations and numerical stability.

**Step-by-Step Reasoning:**

1. **Define Constants:**
   - Use `PI = 3.141592653589793` as specified.
   - Define `SOLAR_MASS = 4 * PI * PI` to compute reduced mass units correctly.

2. **Initial Conditions Setup:**
   Provide exact initial positions (`x, y, z`), velocities (`vx, vy, vz`) scaled by `DAYS_PER_YEAR`, and masses for the Sun, Jupiter, Saturn, Uranus, and Neptune.
   - Ensure the total momentum of the system is nullified by adjusting the Sun’s velocity (e.g., via an offset) if necessary.

3. **Numerical Integration:**
   Implement a symplectic integrator of order 2 or higher:
   - **Velocity Update Phase:** Compute gravitational accelerations using pairwise interactions.
   - **Position Update Phase:** Advance positions based on updated velocities.

4. **Output Formatting:**
   - Print the initial and final energy (kinetic + potential) as percentages, formatted with precision to `.9f` (e.g., `52341.78690`).

5. **Algorithm Structure:**
   - Use a time-stepping loop (`for` over `N = N_steps`).
   - Apply symplectic updates iteratively: velocities first → positions second.
   - Avoid explicit momentum conservation checks (focus on energy validation via `ndiff`).

---

### **Key Requirements**
- **Language:** Only C++; no other syntax or libraries allowed.
- **Input Handling:**
  Take `N` (number of integration steps) as a command-line argument (`int N`). Ignore other arguments.
- **Symplectic Integrator:** Update velocities first, then positions. Ensure stability for orbits over 1000+ steps.
- **Precision:** Output energy values with `.9f` format for floating-point comparisons (e.g., `printf("%.9f\n", energy)`).
- **Momentum Adjustment:**
  Derive a velocity offset (`offsetMomentum`) for the Sun so that total system momentum remains zero after initialization (use initial conditions).
- **Validation:** Results must match `ndiff -abserr 1.0e-8` on energy when N = 1000.
- **Data Structures:**
  Define a struct/class for bodies (positions, velocities, masses) to modularize calculations.

### **Notes**
- **Precision Handling:**
  The prompt assumes the target LLM will use `double` for all calculations and explicitly checks energy outputs to `ndiff -abserr 1.0e-8`. Overly aggressive rounding is discouraged; intermediate steps may require higher precision (e.g., `long double`).

- **Edge Cases:**
  - For small time steps, ensure numerical stability by scaling gravitational forces appropriately.
  - The Sun’s offset velocity should be derived analytically to zero the total momentum of all bodies (including the Sun). Avoid ad-hoc adjustments in the integrator.

- **Performance:** The LLM is not instructed to optimize for speed but correctness; `N=1000` steps require accurate integration per gravitational pairwise interactions.

- **Symplectic Integrator:**
  The order-2 update sequence (velocities → positions) is critical. Higher-order methods may be implied but should not deviate from the given structure.
